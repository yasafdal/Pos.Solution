# Payment Module & Phase 1 Cash Payment Processing Specification

## 1. Overview
The Payment Module manages order lifecycle, itemized line pricing (including product modifiers), calculation of totals, and payment execution starting with Phase 1 Cash Payment Processing.

## 2. Database Schema (`POS.Api/Database/PaymentModule.sql`)
- **`Orders`**
  - `OrderId` BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `OrderNumber` VARCHAR(30) UNIQUE NOT NULL
  - `BranchId` INT NOT NULL
  - `OutletId` INT NOT NULL
  - `CashierId` VARCHAR(450) NOT NULL
  - `ShiftId` BIGINT NULL
  - `OrderType` VARCHAR(20) NOT NULL (e.g. `DINING`, `TAKEAWAY`)
  - `OrderStatus` VARCHAR(20) NOT NULL (e.g. `PENDING`, `COMPLETED`, `CANCELLED`)
  - `PaymentStatus` VARCHAR(20) NOT NULL (e.g. `UNPAID`, `PAID`, `REFUNDED`)
  - `Subtotal` NUMERIC(18,2) NOT NULL
  - `DiscountAmount` NUMERIC(18,2) NOT NULL DEFAULT 0.00
  - `TotalAmount` NUMERIC(18,2) NOT NULL
  - `CreatedAt` TIMESTAMP WITHOUT TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP

- **`OrderItems`**
  - `OrderItemId` BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `OrderId` BIGINT NOT NULL (FK to `Orders`)
  - `ProductId` INT NOT NULL
  - `ProductName` VARCHAR(200) NOT NULL
  - `Quantity` NUMERIC(18,3) NOT NULL
  - `BasePrice` NUMERIC(18,2) NOT NULL
  - `ModifierTotal` NUMERIC(18,2) NOT NULL DEFAULT 0.00
  - `UnitPrice` NUMERIC(18,2) NOT NULL
  - `LineTotal` NUMERIC(18,2) NOT NULL

- **`OrderItemModifiers`**
  - `OrderItemModifierId` BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `OrderItemId` BIGINT NOT NULL (FK to `OrderItems`)
  - `ModifierOptionId` INT NOT NULL
  - `ModifierName` VARCHAR(100) NOT NULL
  - `AdditionalPrice` NUMERIC(18,2) NOT NULL

- **`Payments`**
  - `PaymentId` BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `OrderId` BIGINT NOT NULL (FK to `Orders`)
  - `PaymentMethod` VARCHAR(30) NOT NULL (e.g. `CASH`)
  - `Amount` NUMERIC(18,2) NOT NULL
  - `AmountTendered` NUMERIC(18,2) NOT NULL
  - `ChangeAmount` NUMERIC(18,2) NOT NULL
  - `PaymentStatus` VARCHAR(20) NOT NULL (e.g. `SUCCESS`, `FAILED`)
  - `ReferenceNumber` VARCHAR(100) NULL
  - `ProcessedBy` VARCHAR(450) NOT NULL
  - `PaidAt` TIMESTAMP WITHOUT TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP

## 3. Business & Security Rules
1. **Required: authoritative pricing (not complete).** Current order creation calculates arithmetic on the server but trusts submitted base prices, modifiers and discounts. Database-price validation is still required.
2. **Atomic Transactions:** Order creation and payment processing each use an EF Core transaction. Receipt retrieval and printing run after payment commits, outside that transaction.
3. **Required: durable duplicate prevention (not complete).** Current payment processing checks PAID before its transaction; persisted idempotency keys and order-level concurrency protection are still required. Receipt retries never call payment processing.
4. **Required: checkout authorization (not complete).** Existing order/payment endpoints still need authenticated cashier, branch/terminal and active-shift enforcement. The new receipt endpoint is authenticated and owner/Admin restricted; this does not secure the upstream checkout endpoints.
4. **Idempotent DB Setup:** The initialization SQL script uses `CREATE TABLE IF NOT EXISTS` and explicit constraints without disruptive drops.

## 4. API Endpoints
- `POST /api/orders` — Create a new order with items and modifiers.
- `GET /api/orders/{id}` — Retrieve order details and payment status.
- `POST /api/payments` — Process payment (Cash) for an order, computing change and updating order status.
- `GET /api/orders/{id}/receipt` — Read persisted paid receipt snapshots, successful payments and current branch/terminal metadata (authenticated owner/Admin).

## 5. POS Client Checkout Workflow (`NewSale.razor`)
- **Proceed to Payment Modal:** Displays authoritative server total, payment method (Cash selected by default), cash tendered numeric input, real-time change calculation (`Tendered - Total`), and Confirm Payment button.
- **Payment/printing separation:** Clear the cart only after a successful payment response; show a receipt preview with manual Print Receipt / Skip Printing. A receipt load/print failure offers Retry Print without resubmitting payment.
